# 人脸阈值现场标定操作清单

> 适用：FaceFlow 边缘盒 + 录入端部署到现场后、正式启用前的必做步骤。
> 目的：把代码中的**经验默认阈值**换成**你这个现场/这组模型实测出来的阈值**。

## 1. 三个阈值速览

| 阈值 | 配置键 | 默认值 | 作用 | 标低的风险 | 标高得风险 |
|---|---|---|---|---|---|
| 检测置信度 | `det_thresh` | 0.5 | SCRFD 人脸检测 | 画框/倒影误当人脸（误检） | 侧脸/暗光/小脸漏检 |
| 识别/回查 | `recog_thresh` | 0.40 | 1:N 识别、历史来访回查 | 不同人被认成同一人 | 老顾客回查不到 |
| 1:1 人证 | `verify_thresh` | 0.50 | 录入端现场照 vs 证件照 | 冒名者通过 | 本人被拒 |

约定：`verify > recog` 是有意的（办证场景严，客流场景宽），标定时不要反过来。

## 2. 前提

- [ ] 已部署**最终要用的那组 ONNX 模型**（SCRFD + ArcFace + 活体），而不是临时模型
- [ ] 边缘盒摄像头已装好，角度/光线与正式运营一致
- [ ] 录入端摄像头可用（1:1 标定需要）
- [ ] 能访问边缘盒（Web 配置界面 `:8180` 或直接改 `edge_box.json`）与管理后台

## 3. 准备样本（约 30~50 人）

| 类型 | 数量 | 说明 |
|---|---|---|
| 正样本对 | ≥ 30 人 × 每人 ≥ 3 组 | 同一个人两张照：现场照① vs 现场照②；现场照 vs 证件照（跨域，最重要） |
| 负样本对 | ≥ 50 对 | 不同人的现场照互比（A 现场 vs B 现场）、现场 vs 他人证件照 |

> 为什么 30~50 人：人太少分布不稳（个别特征离群值会带偏阈值）。预算有限时最少 20 人、60 对负样本。
>
> 拍摄要求：与运营一致的光照、正脸、自然表情；包含少量侧脸（±30°）与戴眼镜样本，避免全部"完美正脸"过于乐观。

## 4. 推荐流程

### 4.1 提取特征

离线脚本法（推荐，独立于系统 UI，可控性最好）：

```bash
# 用 python + onnxruntime 包（pip install onnxruntime opencv-python）
# 对每张照片跑：SCRFD 检测 -> 5点对齐(ArcFaceDst112) -> ArcFace 提取 512 维
# 输出 CSV：file_a, file_b, pair_type, cosine
```

脚本骨架（`scripts/calibrate.py`，算法与 edge-box `src/feature/align.h` 一致）：

```python
import cv2, numpy as np, onnxruntime as ort

ARC_DST = np.array([[38.2946,51.6963],[73.5318,51.5014],[56.0252,71.7366],
                    [41.5493,92.3655],[70.7299,92.2041]], dtype=np.float32)

def l2norm(x): return x / np.linalg.norm(x)

def extract(rec_sess, aligned_bgr):
    # BGR->RGB, (v-127.5)/128, NCHW
    rgb = cv2.cvtColor(aligned_bgr, cv2.COLOR_BGR2RGB)
    x = (rgb.astype(np.float32) - 127.5) / 128.0
    x = x.transpose(2, 0, 1)[None]                       # 1,3,112,112
    out = rec_sess.run(None, {rec_sess.get_inputs()[0].name: x})[0]
    return l2norm(out[0].astype(np.float32))

def cosine(a, b): return float(np.dot(a, b))
```

> 对齐（5 点相似变换到 ArcFace 112）直接复用 edge-box `face_align` 的算法与坐标。
> 若现场有检测模型，先 detect 拿 5 点；无关键点模型时对正脸图可直接 `cv2.resize` 到 112。

### 4.2 看分布

对输出 CSV 按 `pair_type` 分组统计：

```
正样本对（现场-现场）:   均值 0.62   P5 0.45  P95 0.78
正样本对（现场-证件照）: 均值 0.48   P5 0.33  P95 0.62   ← 跨域明显偏低，正常
负样本对:               均值 0.10   P95 0.21  P99 0.28
```

### 4.3 定阈值

策略（按误识风险倒推）：

1. **`recog_thresh`（1:N/回查）**：取负样本对的 **P99**（保证 99% 不同人不会互相命中）。上例 → `0.28 ~ 0.30`。再验证正样本 P5 仍高于它（上例 0.45 > 0.30 ✅）；若现场照-证件照的正样本 P5 低于候选值，说明跨域太差，优先查采集质量而非继续降阈值。
2. **`verify_thresh`（1:1 人证）**：取现场-证件照正样本对的 **P1~P5** 附近（保证 95% 本人通过），同时 > 负样本 P99 一定余量（至少 +0.10）。上例 → `0.35~0.38`。
3. **`det_thresh`**：用 500 帧含无人的监控画面跑检测，统计误检框；同时统计真实顾客的检出率。取"误检≈0 且检出 ≥ 99%"的最低值。常见结果仍在 0.4~0.6，属正常。

> 若你的模型是社区常见版本（InsightFace 原版导出），最终值通常落在：
> `det 0.40~0.60`、`recog 0.30~0.45`、`verify 0.40~0.55`。
> 若离这个区间很远（如 recog 需 < 0.2 才不漏），先怀疑采集/对齐环节，而不是硬调阈值。

### 4.4 下发配置

三处生效点，改任意一处即可（优先级见下）：

| 位置 | 方法 |
|---|---|
| 边缘盒本地 | 编辑 `edge_box.json` 的 `det_thresh/recog_thresh/verify_thresh` → Web 界面 `POST /api/reload` 热重载 |
| 边缘盒 Web 界面 | 浏览器打开 `http://<盒IP>:8180` → 全局参数在线编辑 → 保存热重载 |
| 管理后台下发 | 设备页「配置下发」弹窗下发 JSON（`{"det_thresh":0.5,"recog_thresh":0.30,...}`），边缘盒轮询拉取并热重载 |
| 后台历史回查 | 管理后台环境变量 `HISTORY_THRESHOLD`（默认 0.40），重启生效 |

> 优先级：后台下发的远程配置优先，但设备身份/Web 安全字段本地优先（防循环）。改完以 `GET /api/config` 返回值为准核对。

## 6. 常见坑

- **同机位连拍偏乐观**：同一摄像头几秒内连拍，光照/姿态几乎不变，得到的正样本分布虚高。样本要跨时段、微调角度/表情。
- **证件照-现场照天然偏低**：ArcFace 对跨域对普遍低 0.08~0.15，正常；不要因为"现场-现场"分布好看就忽略跨域组。
- **人数太少不可信**：少于 20 人的分布，P99 意义不大。
- **夜色/逆光**：不同光照下的特征差异大，尽可能在运营时段采集。
- **换模型必须重标**：模型一变，整个分布都可能移动，阈值作废。

## 7. 部署后验证清单（对标定结论的最终确认）

- [ ] 已知老顾客进门：回查能命中（后台「历史回查」页查得到，相似度 > recog_thresh）
- [ ] 两名相貌相近的同事依次进门：不会互相命中（客流不串）
- [ ] 录入端：本人持证当场能通过（verify > verify_thresh）；拿他人证件被拒
- [ ] 无人店面跑 10 分钟：边缘盒日志无"误检人脸"刷屏
- [ ] 若任一验证失败：回到 4.3 微调对应阈值，重跑该单项即可，不必全量重标
